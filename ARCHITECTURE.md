# Architecture

*(Polish original: [docs/pl/ARCHITECTURE.md](docs/pl/ARCHITECTURE.md).)*

## Layout
```
Sources/OpenCommanderCore/      SwiftPM package: all the logic, testable without UI
  Models/        FileEntry, PanelState, FileOperation (+Report/Progress/Conflict), OperationError
  FileSystem/    DirectoryLister, FileSorter, FileService (mkdir/rename), Locations (volumes, places)
  Operations/    FileOperationEngine (copy/move/trash), OperationCenter (queue, UI state), RemoteTransferEngine
  Persistence/   SettingsStore (UserDefaults, JSON), TempJournal
  Network/       RemotePath/RemoteLocation, ConnectionProfile, SecretStore (Keychain), ProfileStore, TrustedHosts, HostKeyVerifier,
                 FileProvider (+Capabilities), NetworkError (+Redactor), ConnectionManager
Sources/OpenCommanderRemote/    protocols: SFTP/ (Citadel), WebDAV/ (URLSession + XMLParser), FTP/ (libcurl), RemoteModule (factory)
Sources/CCurl/                  system module: the libcurl header from the macOS SDK + inline functions wrapping the variadic `curl_easy_*`
Tests/OpenCommanderCoreTests/   tests on temporary directories (+ FakeProvider: an in-memory server)
Tests/OpenCommanderRemoteTests/ tests against local servers inside the test process (SFTP, HTTP/WebDAV, FTP, TLS)
OpenCommander/                  the app (SwiftUI + AppKit)
  App/           entry point, AppState, menus/shortcuts, RootView
  Features/Browser/     panel: table, breadcrumbs, status bar
  Features/Sidebar/     sidebar
  Features/Operations/  operations area, sheets (name, conflict)
  Features/Connections/ connection manager, form, host key and password prompts, trusted hosts
project.yml     Xcode project definition (XcodeGen)
```
Tabs: `PanelTabs` (Models) holds a list of `PanelState`; each tab is a full panel state, and a `Workspace` is a snapshot of both panels' tabs. A separate `TabState` is not needed.

## Decisions
- **Minimum macOS 14.4:** `@Observable`, `onKeyPress`, `defaultScrollAnchor` and a mature multi-selection `Table`. Targeting macOS 13 would need `ObservableObject` and workarounds.
- **No App Sandbox:** a file manager has to work on arbitrary folders, and the sandbox forces security-scoped bookmarks for every location, including on each launch and for browsing the whole disk, which breaks the main use case. The app is signed with the Hardened Runtime and **does not request Full Disk Access**; access to protected folders (Desktop, Documents, external volumes) goes through the standard system consent mechanism (TCC). Consequence: distribution outside the Mac App Store. Changing this decision requires adding bookmarks (see the ROADMAP).
- **File identity = path** (`FileEntry.id`), never a table index (for remote items: the full `ocremote://` URL). After a rename or move the panel explicitly selects the new URL. Entries are built from the given folder (the system may return `/private/var` instead of `/var`).
- **Stale results:** `PanelState` numbers loads (`generation`) and cancels the previous task; the result of an older load is dropped. A failed navigation keeps the previous location and shows an error.
- **Concurrency:** listing in `Task.detached` with cancellation propagation; file operations in the engine off the main thread; `OperationCenter` (MainActor) runs one job at a time.
- **Operation engine:** copy → temporary file `.opencommander-tmp-<uuid>` in the destination folder → rename. Same volume: moving through `rename`; another volume: copy, then the source is removed after success. Replace: the old item goes to the Trash (an injected `Trashing`, a fake in tests), and only then the new one. Copying goes through `copyfile(3)` (`FileCopier`): metadata, APFS cloning when possible, byte progress from the callback and cancelling in the middle of a file (the temporary file is removed, the source untouched). The total size is computed from metadata before the start (without reading contents).
- **Temporary file journal** (`TempJournal`, Application Support): an entry before the first change on disk. Kind `copy` (an incomplete copy) is removed on startup; kind `movedSource` (the original temporarily under a temporary name during a rename) is **restored**, never deleted. Cleanup touches only files with the `.opencommander-tmp-` prefix.
- **Symbolic links** are copied as links; protection against copying into a descendant works on paths with resolved links and without case sensitivity (conservatively).
- **Progress:** bytes where measured (copying data), otherwise items. `OperationCenter` smooths the speed (EMA) and estimates the time remaining; APFS cloning and moving through rename are instant, so they give no intermediate progress.
- **Refreshing:** `DirectoryWatcher` (a DispatchSource on the folder descriptor, 0.3 s delay) in `PanelState`; it reports changes of the folder's direct children. This is not FSEvents: it does not see changes deep in the tree or in file contents.
- **Dropping:** `DropPlanner` (Core) chooses move or copy and filters out items already in the destination; execution goes through the normal `OperationCenter` queue, so every safeguard of the engine applies.
- **Stage 3 tools (Core, tested):** `BatchRename` (plan → execute only `ok` items, no overwrites), `FolderComparison` (metadata, one-sided folders are not expanded), `DuplicateFinder` (size → SHA-256, cancellable, on demand only), `RecursiveSearch`. UI in `Features/Tools`.
- **Panel divider:** an own `Layout` (`TwoPaneSplit`): an offset in pixels clamped in the layout, no `GeometryReader` and no `HSplitView`.
- **Tabs:** always ≥ 1 tab in a panel (the last one cannot be closed; ⌘W then closes the window), limit 10; a new tab duplicates the location and sort order of the active one; a background tab refreshes when selected. `AppState` creates tabs with a factory holding a weak reference to itself (creation in `init`, before `self` is ready).
- **Workspaces:** a save = a snapshot of both panels' tabs (+ active tab and panel); opening replaces all tabs. Settings from earlier versions (without tabs) still load.
- **No `HSplitView` between panels:** a nested split view (`HSplitView`) inside a `NavigationSplitView` with `.inspector` fell into a loop of minimum size changes and crashed the app on startup with the info panel open (reproducibly 8/8 in an isolated test; after switching to an `HStack`, 0 crashes in 16 launches). Consequence: two equal panels, replaced by the own draggable divider (no `GeometryReader`).
- **Breadcrumbs:** a `ScrollView` plus explicit scrolling to an end marker; no coupling of size to the container.
- **Filter ≠ search:** the filter works on the panel's loaded entries (`FileFilter`) and always trims the selection to the visible items; recursive search is a separate stage 3 feature.
- **Folder size:** on demand only (`FolderSizer`), cancellable, reports unreadable items instead of hiding them.

## Network layer (stage 4)
- **Location identity:** a remote address is `ocremote://<connection-uuid>/<percent-encoded components>` (unreserved characters only, per component). So it cannot be confused with `file://`, the same path on two servers is two different items, and spaces, `#`, `%`, `?`, `&` and Unicode survive the encoding. `RemotePath` keeps a list of components and never goes above the root; `LocalMapping` blocks path traversal when downloading.
- **Responsibilities:** `ConnectionProfile` (configuration, no secrets) → `ConnectionManager` (profiles, Keychain, sessions, reconnecting, test) → `FileProvider` (one implementation per protocol: `SFTPProvider`, `WebDAVProvider`, `FTPProvider`) → `RemoteTransferEngine` (transfers in the queue) / `PanelState.remoteLister` (listing). Core does not depend on any network library; the `OpenCommanderRemote` module is injected (`RemoteModule.install`).
- **Operations:** `FileOperationEngine` delegates everything that involves remote addresses to `RemoteOperationHandling`. Allowed: copying local→remote (upload) and remote→local (download), and `OperationKind.delete` (permanent, remote only). Rejected: moving local↔remote (no source is ever deleted), server→server, copying onto itself. Upload: a temporary name on the server → size check → rename; download: a temporary file registered in `TempJournal` → size check → (replace: the old one to the Trash) → move. Cleanup touches only our own `.opencommander-tmp-*` (with a short retry, because the server may finish a write after a drop). After a lost connection nothing destructive is retried automatically; `OperationCenter.retryFailed` is a manual retry of only the failed items from the beginning.
- **Secrets:** `SecretStore` (Keychain: generic password, `WhenUnlockedThisDeviceOnly`, no iCloud; `InMemorySecretStore` in tests). A profile stores only a `SecretRef` (a UUID). "Session only" passwords live in a separate in-memory store and disappear on disconnect. `Redactor` masks secrets, data in URLs, Authorization/Cookie headers and PEM blocks in all error messages.
- **SFTP:** Citadel 0.12.1 (MIT) on the `swift-nio-ssh` fork (`Wellz26`, 0.3.7). *Risk:* the fork is maintained by a single author, and Citadel stays pinned with `exact`; changing the version requires going through the tests again. Citadel supports only Ed25519 / ECDSA host keys, so servers with only RSA/DSA host keys fail key exchange negotiation. Host key trust: `HostKeyVerifier` (unknown → ask, changed → block without asking, a different key type = a change), a SHA256 fingerprint of the OpenSSH key blob; saved only after acceptance. Citadel has no `lstat`, so the kind of an item (including a symlink) comes from the parent directory listing (a 2 s cache); requests are serialized by `AsyncMutex` and have a time limit (after it expires the session is closed and the next action reconnects).
- **WebDAV:** `URLSession` without a manual Authorization header: credentials only as an answer to a Basic/Digest challenge from the base host (after the first Basic challenge the header is attached right away so large PUTs are not sent twice); redirects are handled by an own loop (same host and port, no HTTPS→HTTP, limit 5), and `URLSession` never follows them on its own. The base path from the address (for example `/remote.php/dav/files/ola/`) is the root of the view. 207 responses: `XMLParser` with namespaces (`DAV:`), no external entities, documents with DOCTYPE/ENTITY rejected, 16 MB limit; an href (relative / absolute, encoded / raw Unicode) is resolved against the base, entries outside the base/host/directory and with `..` are rejected, and the directory is not its own entry. Per-resource errors do not break the list. `DELETE` of a collection is recursive on the server, so the provider refuses to delete a non-empty directory (the engine does the recursion). Info.plist has `NSAllowsArbitraryLoads` because ATS would block HTTP; HTTPS certificate validation stays standard, and HTTP is allowed only through `allowInsecure` in the profile.
- **FTP/FTPS:** the system libcurl (`CCurl`), one handle per provider, operations in sequence on a queue, `curl_easy_reset` keeps the connection. FTPS: `CURLUSESSL_ALL` (+ `AUTH TLS` in explicit mode, `ftps://` in implicit mode), TLS capped at exactly 1.2 (servers such as ProFTPD require TLS session reuse on the data channel, which libcurl does reliably only in 1.2; with 1.3 the server answers 425), `VERIFYPEER=1`, `VERIFYHOST=2`; the `USE_SSL_FAILED` error is mapped to a refusal, not to a fall back to plain FTP. Passive mode, `FTP_SKIP_PASV_IP=1`, binary transfers, absolute paths (`ftp://host//path`), names percent-encoded in the URL, and CR/LF/NUL rejected in `QUOTE` commands. Listing: MLSD, and on 500/501/502/504 LIST (`reliableMetadata=false`). `stat` comes from the parent directory listing; before changes (mkdir / rename / delete / upload without overwrite) we check the state with a fresh listing. We capture only server replies (`CURLINFO_HEADER_IN`), never commands (which contain the password). `CAINFO` (an internal parameter used in tests) *narrows* trust to the given certificate; it does not disable verification.
- **Panels:** `PanelState.remoteLister` (injected) lists remote locations; a remote panel has no change watcher, free space or recursive search; back/forward history works across local and remote; saving settings never stores a remote address (after a restart the panel returns to the home folder). Local-only actions (Quick Look, Finder, favorites, batch rename, comparison, duplicates, eject) are disabled for remote items.
- **Prompts to the user** (`HostKeyRequest`, `CredentialRequest`) wait on a `CheckedContinuation` and are queued; one view presents them at a time (above the connection manager, if it is open). The default action for a host key is "Don't trust".

## Known architecture limitations
- No file system change observation (FSEvents): refreshing after operations and ⌘R.
- Before copying, the metadata of the whole tree is scanned (total size); for huge trees that is a moment without a progress bar.
